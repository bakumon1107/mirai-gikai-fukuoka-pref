## 1. 背景と目的

現行トップは「テーマ別の議案カード」が主役になっている。しかし福岡県の議案は
本文がネットに公開されず情報が薄く、多くが工事請負契約など暮らしとの距離が遠い。
一方、知事記者会見（ほぼ隔週）・委員会（閉会中も開催）・一般質問は中身が豊富なのに、
トップでは小さなバナーリンクしかない。結果として、閉会中のトップは
「止まっているサイト」に見える。

目的は2つ。

1. **更新頻度の高い情報から順に並べ**、閉会中でも「動いている」サイトに見せる。
2. **お堅くない、気軽に見に来られる**トーンにする。

セクション順は更新頻度の高い順に
**知事会見 → 定例会 → 委員会 → 一般質問 → テーマ → 予算・議案**。
議案は個別カードを並べず件数の要約に留め、見出しや議題は「問いかけ」の言い回しにする。
定例会は「年4回の議会の本番」として位置づけを明示し、落としすぎない。

### 1.1 確定した方針

| 論点 | 決定 |
|---|---|
| スコープ | **設計書の作成のみ**。実装は別タスク |
| ナビ刷新（原案§4.1） | **PC横ナビ + スマホボトムナビを両方入れる** |
| 見出しフォント | **Zen Maru Gothic を weight 700 の1ウェイトのみ導入**し、**Lexend Giga は廃止** |
| テーマタイルのリンク先（5.8節） | **`/search?q=<検索語>`**。テーマページは作らない |
| 議案の件数の切り口（5.9.1節） | **審議状況（`status`）で出す**。参照デザインの内容分類（条例／工事の契約等）はDBに無いため不採用 |
| 配色（2章） | **現行サイトの薄紫系に揃える**。文字・塗りは `#5a5591`。緑（`#2aa693` / `#17705F`）は不採用 |
| 会期中モード（5.3節） | **段階1（文言差し替え）→ 段階2（ヒーロー差し替え）の2段階**で実装する |

## 2. デザイントークン設計

配色は**現行サイトの薄紫系に揃える**（原案§5、参照 `会期中モード 薄紫.dc.html`）。
参照デザイン `top-desktop.html` / `top-mobile.html` はティール時代の配色なので、
**色については本章を正**とし、構成・余白・文言のみをあちらから読む。

### 2.1 追加するカラートークン

`web/src/app/globals.css` の `@theme inline` に追加する。
名前空間は **`pref-*`** とする。

> **`--color-mirai-*` に足さないこと。** このリポジトリは本家 team-mirai の
> フォークで、`mirai-*` は上流由来の共通トークン。ここに県版固有の色を足すと
> 上流と同期したときに衝突する。県版で増やす色は `pref-*` に隔離する。
> （原案§5は「既存の命名 `--color-mirai-*` に揃える」としているが、
> フォーク運用の都合を優先してこちらを採る。）

**既存トークンで足りるもの（新設しない）**

| テーマタイルのアイコン面（紫系） | `--color-mirai-gradient-start` | `#dbd3f9` |

### 2.2 配色の原則

原案§5 が定めた運用ルール。実装時のレビュー観点になる。

1. **紫のベタ塗り＋白文字は使わない。** 選択中・状態ピルは
   `pref-pill-bg`（淡い紫）＋ `pref-pill-text`（濃い紫）の組み合わせで表現する。
2. **黄色は使わない。** サイトの紫と黄は補色関係でぶつかるため、原案の黄系
   （`#FFE7A8` 等）は廃止し、**紫＋ベージュの2系統**にする。
   テーマタイルの差し色としてコーラルのみ加える。
3. **`#a495d6` / `#7a6cc0` は文字・塗りに使わない。** 白文字とのコントラストが
   それぞれ 2.68:1 / 4.44:1 で 4.5:1 に届かない（検算済み）。
   `#a495d6` は枠線・フォーカスリング等の装飾に限る。
   文字と塗りには `pref-accent`（`#5a5591`、白比 6.68:1）を使う。
4. **強調表示**（「つぎはここ」「いま開会中」「いまここ」）は
   枠 `pref-accent` 2px ＋ 面 `pref-surface-tint` で統一する。

### 2.4 既存ページへの影響

`--primary: #a495d6` / `--primary-accent: #7a6cc0` / `.bg-mirai-gradient` は**据え置く**。
議案・予算・事務事業評価・チャットなど既存ページの見た目は変わらない。
`pref-*` はトップページの新セクション専用に使う。

`pref-accent`（`#5a5591`）は既存の `--primary`（`#a495d6`）を暗くした同系色なので、
トップと既存ページが並んでも系統は揃って見える。**緑案のような二色併存は起きない。**

なお `Button` / `Badge` の `default` variant は `.bg-mirai-gradient`（薄紫グラデ）だが、
本設計は影・グラデーションを使わない方針（2.5節）なので、トップの新セクションでは
`variant="outline"` かクラス上書きで `pref-*` に寄せる。実装時に共通ラッパを1つ作る。

**`meta theme-color` は `#2aa693`（旧ティールの名残）から `#a495d6` に更新する**
（原案§5）。`app/layout.tsx` の `viewport.themeColor`。
`NextTopLoader` の色も併せて `#5a5591` にする。

### 2.5 角丸・余白・影

| 対象 | 値 |
|---|---|
| ヒーロー・大ブロック | 28〜36px |
| カード | 22px |
| タイル | 18px |
| ピル | 999px（`rounded-full`） |
| セクション間 余白 | PC 40〜48px / スマホ 28〜32px |
| PC 左右マージン | 64px |
| タップ領域 | 最小 44×44px |

**影とグラデーションは使わない。** 面の区別は背景色と `pref-divider` の線で行う。
これは既存の `sm:shadow-lg`（`MainLayout`）や `.bg-mirai-gradient` と方向性が異なるため、
トップページでは `MainLayout` の shadow が付かない経路を通す必要がある（4.2節）。

## 3. フォント設計

### 3.1 Zen Maru Gothic の追加

`web/src/app/layout.tsx` に追加する。

```ts
import { Noto_Sans_JP, Zen_Maru_Gothic } from "next/font/google";

const zenMaruGothic = Zen_Maru_Gothic({
  variable: "--font-zen-maru-gothic",
  subsets: ["latin"],
  weight: ["700"],
});
```

`globals.css` の `@theme inline` に追加:

```css
--font-rounded: var(--font-zen-maru-gothic);
```

- **weight は `700` の1つだけ。** 参照デザインは見出しにほぼ 700 しか使っておらず、
  原案§5の 500 は実使用箇所がないため導入しない。
- `subsets` に `japanese` は**存在しない**（`next/font` の型定義で確認済み。
  `Zen_Maru_Gothic` が受け付けるのは `cyrillic | greek | latin | latin-ext`）。
  これは既存の `Noto_Sans_JP` と同じ状況で、**日本語グリフは preload されず
  unicode-range で遅延取得**される。つまり初期表示のクリティカルパスは太らない。
- `display` はデフォルトの `swap`。日本語見出しは一瞬 Noto Sans JP で描画されてから
  差し替わる（既存の日本語表示と同じ挙動）。

### 3.2 適用範囲（限定列挙）

`font-rounded` を当てるのは以下だけ。**本文・ナビ・ラベル・補足テキストは
Noto Sans JP のまま**にする（触れるグリフ数を抑え、ダウンロード量を減らすため）。

- h1（ヒーロー見出し）
- h2（各セクション見出し）
- h3（下段カードの見出し）
- 委員会カードの問いかけ見出し
- 定例会カードの「◯月」
- テーマタイルの漢字一文字アイコン

### 3.3 Lexend Giga の廃止

以下をすべて削除する。

- `web/src/app/layout.tsx` の `Lexend_Giga` import・定義・`body` の `variable` 付与
- `globals.css` の `--font-lexend: var(--font-lexend-giga);`
- `globals.css` `@layer components` の `.font-lexend { ... }`

根拠:

- 実使用は [web/src/components/top/hero.tsx](../../web/src/components/top/hero.tsx) の2箇所のみ。
  23行目は `siteConfig.features.showTeamMiraiSection` が `false` のため
  **空文字をレンダリングしている**。35行目は `Scroll` の10px表示。
- **この `Hero` コンポーネントは新デザインで丸ごと撤去される**（5.3節）ため、
  廃止後に参照は残らない。
- `subsets: ["latin"]` 指定により**5ウェイトが実際に preload されている**。
  削除はクリティカルパスの純粋な改善になる。

### 3.4 コスト見積もり

現状の実測値（`web/.next/static/media`）:

| 項目 | 値 |
|---|---|
| woff2 ファイル数 | 147 |
| 合計サイズ | 5.3MB（Noto Sans JP 3ウェイト + Lexend Giga 5ウェイト） |
| かな・ラテン等の軽いチャンク | 97ファイル / 平均 19KB |
| 漢字密集域のチャンク | 50ファイル / 平均 72KB |

Zen Maru Gothic 700 の追加でディスク上は **+約1.7MB**。
実ダウンロードは見出しが触れるチャンクのみで **概算 80〜200KB**、しかも遅延取得。
Lexend Giga 5ウェイトの削除で preload 対象が減るぶん、初期表示はむしろ改善が見込める。

## 4. ページ構成

### 4.1 セクション順

**PC（`pc:` = 1000px 以上、参照デザインは 1280px）**

1. ヘッダー（ロゴ / グローバルナビ / 検索）
2. ヒーロー：会期ステータスピル + 見出し + **最新の知事会見カード**（2カラム）
3. 定例会の帯（年4回、4枚横並び）

### 4.2 ブレークポイントとレイアウト幅

**このリポジトリの `md:` は 700px**（Tailwind 既定の 768px ではない）。
PC判定には独自の `pc:`（1000px）を使う。`globals.css` の定義:

```css
--breakpoint-sm: 500px;
--breakpoint-md: 700px;
--breakpoint-pc: 1000px;
--breakpoint-pcl: 1400px;
```

参照デザインの 1280px レイアウトは `pc:` 以上に適用し、
700〜1000px は中間レイアウト（2カラム → 1カラム、委員会カードは1列）として扱う。

**レイアウト幅の制約を外す方法**: 現在 `MainLayout` は通常ページを
`max-w-[700px]` に絞っている（[web/src/components/layouts/main-layout.tsx](../../web/src/components/layouts/main-layout.tsx) 34行目）。
新トップは PC で全幅を使うため、この制約を外す必要がある。

既存の逃がし口 `isWidePage()`
（[web/src/lib/page-layout-utils.ts](../../web/src/lib/page-layout-utils.ts) 27行目）が
`/jimu-jigyo` に対して `max-w-[1440px] mx-auto mt-24` を返しているので、
**ここに `/` を足すだけでよい**。新しい分岐は作らない。

```ts
export function isWidePage(pathname: string): boolean {
  if (pathname === "/") return true;
  return pathname.startsWith("/jimu-jigyo");
}
```

この経路は `sm:shadow-lg` が付かないため、2.5節の「影を使わない」方針とも一致する。

**副作用の確認が必要な点**: `isMainPage("/")` は `true` のままなので、
ヘッダーの `DifficultySelector` はトップに出続ける。新デザインのヘッダーに
難易度セレクタを残すかは実装時に判断し、残さないなら `isMainPage` ではなく
別の判定に切り替える（`isMainPage` は難易度セレクタとチャットサイドバーの
両方に効くため、安易に `/` を外さないこと）。

#### 5.3.3 「会期の流れ」と進み具合の算出

**進み具合**は `start_date` / `end_date` だけで出せる。
令和8年9月定例会なら 9/9〜10/16 で全38日、9/24 時点で16日目。
日数は**両端を含めて数える**（9/9 が1日目）。

**会期の流れ**は4ステップ。

| ステップ | ラベル | 令和8年9月定例会での実日程 |
|---|---|---|
| 1 | 開会・議案の説明 | 9月9日 |
| 2 | 一般質問・代表質問 | 9月15日〜9月25日 |
| 3 | 委員会でくわしく審査 | 9月28日〜9月30日（常任委員会） |
| 4 | 採決・閉会 | **議案採決 10月1日 ／ 閉会 10月16日** |

各行に日付を出し、終わった段階には「おわった」タグ、現在の段階には「いまここ」
（面 `pref-surface-tint`）を付ける。

> **重要 — 採決日と閉会日は別の日**。
> 参照デザインは4ステップ目を「10月16日 採決・閉会」と1行にまとめているが、
> これは**デザイン上の参考表記**であり実日程とは異なる。
> 実際には議案の採決は 10月1日（常任委員長報告・採決）に終わり、
> その後は決算特別委員会が続いて 10月16日 に閉会する。
> **「議案がいつ決まるか」を伝えるのが目的なので、採決日は採決日として出すこと。**
> ステップを5つに割るか、4ステップ目に両方の日付を併記する。
> デザインの日付をそのまま実装しないこと。

**日程データの取得**: 会期日程ページには各日の議事日程（`開会` / `代表質問` /
`一般質問` / `常任委員会` / `議案採決` / `閉会` 等）が日付付きで載っており、
ステップ2〜4を機械的に判定できる。ただし現在の `parseSessionSchedule()` は
**開会日と閉会日しか抽出していない**（5.5.1節）。
段階2を実装するときにパーサーを拡張する。

拡張しない場合でも、原案の指示どおり**行ごと非表示**にすれば開会・閉会の2行で成立する。
段階2の着手判断とパーサー拡張はセットで考える。

### 5.5 定例会の帯

見出し「定例会は年4回。議会の本番です」／
補足「議案の採決と一般質問は定例会で。あいだの期間は委員会が開かれます。」

当年の定例会4回（2月・6月・9月・12月）をカード表示。状態は日付から算出する。

| 状態 | 条件 | 表示 |
|---|---|---|
| `おわった` | `end_date` が今日より前 | リンク「議案・一般質問を見る」等 |
| `いま開会中` | `start_date <= 今日 <= end_date` | 枠 `pref-accent` 2px + 面 `pref-surface-tint` で強調。タグは背景 `pref-pill-bg` / 文字 `pref-pill-text`。説明文は「◯◯を審議中」、下段は「◯月◯日まで」 |
| `つぎはここ` | 次に開会する回 | `いま開会中` と同じ強調スタイル。開会日を表示 |
| `これから` | それ以降 | 前年同月に一般質問データがあれば「昨年の◯月を見る」 |

> **会期中は強調を「開会中の回」だけにする**（原案§4.8）。
> 次の回に `つぎはここ` を併記せず `これから` 扱いにする。

> 閉会中は `つぎはここ` が唯一の強調になる。つまり**強調枠は常に1つだけ**。

**`getAllPastSessions()` は使えない。** repository の実装が
「`is_active = false` かつ published な議案を1件以上持つ会期」に絞っているため、
「一般質問はあるが議案未投入」の会期が落ちる。
**当年の全 `council_sessions` を返す新規 repository 関数を設ける。**

```ts
export async function findCouncilSessionsByYear(
  year: number
): Promise<CouncilSession[]>
```

**状態算出は純粋関数に切り出し、テストを必須とする**（CLAUDE.md 規約）:

- `web/src/features/council-sessions/shared/utils/resolve-session-slot-status.ts`
- `resolve-session-slot-status.test.ts`（同階層）

各月の一行説明（2月＝「新しい年度の予算を決める」など）は固定文言としてここに定義する。

#### 5.9.1 議案の件数集計 — 審議状況（`status`）で出す【決定済み】

参照デザインの「条例 6 / 工事の契約 10 / 購入 2 / 計画 1」という区分は**議案の内容分類**で、
DBにこの情報は無い。`bills.name` から仕分ける仕組みを新たに作る必要があるため、
**既存データにある別の切り口で出すことに決定した。**

候補は `bill_type` と `status` の2つだが、**`status`（審議状況）を採用する。**

**`bill_type` を採らない理由**: 実データの分布が極端に偏っている。
`bill` / `opinion` / `resolution` / `member_bill` の4値のうち、
スクレイプ済み408件中 **`bill` が404件・`member_bill` が4件**で、
`opinion` と `resolution` は0件。会期単位で見ても最新の令和8年9月定例会は
**57件 対 1件**で、チップを並べても情報量がない。

**`status` を採る理由**: 会期の進行に応じて数字が動くため、
「更新頻度の高い情報を前に出す」という本刷新の狙いに合う。

| 会期 | status の分布 |
|---|---|
| 令和8年9月定例会（会期中） | `submitted` 56 / `approved` 2 |
| 令和8年6月定例会（閉会後） | `approved` 34 |
| 令和8年2月定例会（閉会後） | `approved` 87 |

表示は会期の状態で出し分ける。

| 状況 | 表示例 |
|---|---|
| 会期中 | 見出し「いま57件を審議中」＋チップ「審議中 56」「可決 2」 |
| 閉会後・全件同一 status | 見出し「前回の議案はすべて可決」＋チップ「可決 34」 |
| 閉会後・status が混在 | 見出し「◯件中◯件が可決」＋該当するチップを列挙 |

**ラベルは既存の `getCardStatusLabel()` を再利用する**
（`web/src/features/bills/shared/utils/bill-status.ts`）。
`submitted` / `in_committee` / `plenary_session` を「議会審議中」にまとめ、
`approved`「可決」・`rejected`「否決」・`reported`「専決処分報告」を返す関数が既にある。
**トップ用に別のラベル定義を作らないこと。**

件数集計は、既存の `countPublishedBillsByDietSession(councilSessionId, difficultyLevel)` が
会期内総数を返すのみなので新規に必要。`status` ごとの head-count を並列で叩くか、
`status` で group by する RPC を1本用意する。
`getCardStatusLabel()` が3つの status を1ラベルに畳むため、
**畳んだ後のラベル単位で合算すること**（「議会審議中」に3 status ぶんを足す）。

集計は必ず `publish_status = "published"` で絞る（5.9.2節）。

> 参照デザインどおりの内容分類（条例／工事の契約／購入／計画）を出したくなった場合は、
> `bills.name` からの分類ロジックが別途必要になる。11章の論点6として残す。

#### 5.9.2 draft 議案の大量投入が前提になった（#49 / #52）

議案スクレイパー（#52）は10会期ぶんの議案を `docs/data/bills/*.json` として出力済みで、
これらは **`draft` で投入される前提**になっている。#49 はその前準備として
`findFeaturedBillsWithContents` に `publish_status = "published"` を追加し、
draft の議案が `is_featured` を立てられてもトップに露出しないようにした。

件数集計を実装する際も**必ず `publish_status = "published"` で絞ること**。
絞り忘れると、未公開のスクレイプ済み議案が件数に乗り、
画面上の件数と「議案をぜんぶ見る」の遷移先の件数が食い違う。

なお新デザインでは「注目の議案」セクション自体をトップから外すため、
この #49 が守っている経路（`getFeaturedBills`）は最終的にトップから呼ばれなくなる。
議案一覧ページへ移設する際にこのフィルタを落とさないよう注意する（9章 PR7）。

今回この2点を直すかは実装時に判断する。

### 9.1 実装時に守る規約（CLAUDE.md より）

- **インラインカラーコード禁止**。`text-[#xxx]` 等は使わず、`globals.css` の
  トークンを使う。新色は先にトークンを追加する。
- **インラインSVG禁止**。アイコンは `lucide-react` から import する。
- **生 `<button>` 禁止**。`@/components/ui/button` の `Button` を使う。
- **`h-screen` / `min-h-screen` 禁止**。`h-dvh` / `min-h-dvh` を使う。
- 本文テキストは `text-xs` / `text-sm` / `text-base` を使う
  （文字サイズ拡大モードが効くのはこの3つだけ）。
- 外部依存のない計算・変換・判定は `utils/` に純粋関数として切り出し、
  同階層に `*.test.ts` を必ず置く。
- Biome: 2スペース・LF・ダブルクォート・セミコロン・80文字幅。
