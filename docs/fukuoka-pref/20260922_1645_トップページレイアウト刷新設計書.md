# トップページレイアウト刷新 設計書（みらい議会＠福岡県）

作成日: 2026-09-22

デザイナー原案 [docs/fukuoka-pref/レイアウト変更/TOP_PAGE_REDESIGN.md](レイアウト変更/TOP_PAGE_REDESIGN.md)
を、現行コードベースの実態に突き合わせて実装可能な形に落とし込んだもの。
参照デザインは [top-desktop.html](レイアウト変更/top-desktop.html)（PC 1280px）と
[top-mobile.html](レイアウト変更/top-mobile.html)（スマホ 390px）。
これらはデザインツールの書き出しで `support.js` 参照や固定サイズ指定を含むため、
**見た目・文言・構造の参照**としてのみ扱う。

**本設計書のスコープは設計のみ。実装は承認後に別タスク・別PRで行う。**

## 1. 背景と目的

現行トップは「テーマ別の議案カード」が主役になっている。しかし福岡県の議案は
本文がネットに公開されず情報が薄く、多くが工事請負契約など暮らしとの距離が遠い。
一方、知事記者会見（ほぼ隔週）・委員会（閉会中も開催）・一般質問は中身が豊富なのに、
トップでは小さなバナーリンクしかない。結果として、閉会中のトップは
「止まっているサイト」に見える。

目的は2つ。

1. **更新頻度の高い情報から順に並べ**、閉会中でも「動いている」サイトに見せる。
2. **お堅くない、気軽に見に来られる**トーンにする。

セクション順は更新頻度の高い順に
**知事会見 → 定例会 → 委員会 → 一般質問 → テーマ → 予算・議案**。
議案は個別カードを並べず件数の要約に留め、見出しや議題は「問いかけ」の言い回しにする。
定例会は「年4回の議会の本番」として位置づけを明示し、落としすぎない。

### 1.1 確定した方針

| 論点 | 決定 |
|---|---|
| テーマカラー | **`#2aa693` のティール系**を使う。原案§5の `#17705F` への差し替えは**不採用** |
| スコープ | **設計書の作成のみ**。実装は別タスク |
| ナビ刷新（原案§4.1） | **PC横ナビ + スマホボトムナビを両方入れる** |
| 見出しフォント | **Zen Maru Gothic を weight 700 の1ウェイトのみ導入**し、**Lexend Giga は廃止** |

### 1.2 実装前に知っておくべき現状（調査結果）

手戻りの種になるため先に挙げる。詳細は各節で扱う。

1. **`#2aa693` はデザイントークン化されていない。** `@theme inline` にも `:root` にも
   存在せず、[web/src/app/layout.tsx](../../web/src/app/layout.tsx) の `themeColor`（67行目）と
   `NextTopLoader`（80行目）、および `web/public/icons/*.svg` の `fill="#2AA693"` に
   ハードコードされているだけ。**実際のUIアクセントは紫**
   （`--primary: #a495d6` / `--primary-accent: #7a6cc0`）。
2. **`#2aa693` の白文字コントラストは 3.01:1** で、文字色や塗りピルには使えない。
3. **PCナビ用の未使用コンポーネントが残っている。**
   `web/src/components/layouts/desktop-menu/`（8ファイル）はどこからも import されていない。
4. **議員テーブルはDBに存在しない**（`members` / `legislators` 系なし）。
5. **委員会の発言数は一覧用SELECTから意図的に除外されている**（6.2 節）。
6. **記者会見の詳細ページにアンカーが無い**（委員会側には `#topic-N` が実装済み）。
7. **原案§7.5 の「一般質問のリンクが r7-12 に固定」は現状のコードには存在しない。**
   `getLatestSessionWithQuestions()` で最新会期に動的追従済み。論点から落とす。

## 2. デザイントークン設計

### 2.1 追加するカラートークン

`web/src/app/globals.css` の `@theme inline` に追加する。名前空間は **`pref-*`**
とする（本家 team-mirai との同期時に既存の `mirai-*` と衝突させないため）。

| トークン | 値 | 用途 |
|---|---|---|
| `--color-pref-accent` | `#2aa693` | 面・アイコン・枠線・小さな装飾。**文字には使わない** |
| `--color-pref-accent-strong` | `#1f7a6d` | リンク文字・塗りピルの背景 |
| `--color-pref-accent-hover` | `#186257` | hover、および `accent-soft` / `accent-chip` の上の文字 |
| `--color-pref-accent-soft` | `#ddf2ec` | ヒーロー面 |
| `--color-pref-accent-tint` | `#eff7f4` | テーマタイル面・日付チップ |
| `--color-pref-accent-chip` | `#cdebe2` | テーマタイルの漢字アイコン面 |
| `--color-pref-amber-bg` | `#ffe7a8` | 数字チップ・「つぎはここ」バッジの背景 |
| `--color-pref-amber-text` | `#6b4800` | 同上の文字 |
| `--color-pref-amber-border` | `#e8b93a` | 「つぎはここ」カードの枠線 |
| `--color-pref-amber-tint` | `#fff8e6` | 「つぎはここ」カードの面 |
| `--color-pref-coral-bg` | `#fde2d6` | テーマタイル3系統目のアイコン面 |
| `--color-pref-coral-text` | `#7a2f14` | 同上の文字 |
| `--color-pref-coral-tint` | `#fff4f0` | 同上のタイル面 |
| `--color-pref-page` | `#fbf8f1` | ページ背景 |
| `--color-pref-surface-sub` | `#f6f4ee` | 定例会カード等のサブ面 |
| `--color-pref-divider` | `#f0ece2` | 区切り線 |

本文文字色は既存の `--color-mirai-text`（`#1f2937`）を流用する。補足テキストは
原案§5が `#5B6563` を指定しているが、既存の `--color-mirai-text-secondary`
（`#404040`）で代替でき、コントラストもこちらが有利なため**新トークンを足さない**。

### 2.2 `accent-strong` が「元のテーマカラー」である根拠

`#2aa693` を HSL に変換すると `hsl(171, 60%, 41%)`。
`--color-pref-accent-strong` (`#1f7a6d`) は **色相171°・彩度60%を固定したまま
明度だけ 41% → 30% に下げた値**で、`--color-pref-accent-hover` (`#186257`) は
同じく明度 24% の値。色相を一切変えていないため、
「テーマカラーは元のものを使う」という要件を満たしている。

原案§5が提案していた `#17705F` は色相が約167°でわずかにずれるため採用しない。

### 2.3 コントラスト（全て検算済み・WCAG AA 4.5:1 基準）

| 組み合わせ | 比 | 判定 |
|---|---|---|
| `accent-strong` `#1f7a6d` / 白 | 5.17:1 | ✓ |
| `accent-strong` / `pref-page` `#fbf8f1` | 4.87:1 | ✓ |
| `accent-strong` / `accent-tint` `#eff7f4` | 4.75:1 | ✓ |
| `accent-hover` `#186257` / 白 | 7.18:1 | ✓ |
| `accent-hover` / `accent-soft` `#ddf2ec` | 6.15:1 | ✓ |
| `accent-hover` / `accent-chip` `#cdebe2` | 5.67:1 | ✓ |
| `mirai-text` `#1f2937` / `accent-soft` | 12.57:1 | ✓ |
| `mirai-text` / `accent-tint` | 13.48:1 | ✓ |
| `mirai-text` / `pref-surface-sub` `#f6f4ee` | 13.35:1 | ✓ |
| `mirai-text` / `pref-page` | 13.84:1 | ✓ |
| `amber-text` `#6b4800` / `amber-bg` `#ffe7a8` | 6.76:1 | ✓ |
| `amber-text` / `amber-tint` `#fff8e6` | 7.77:1 | ✓ |
| `coral-text` `#7a2f14` / `coral-bg` `#fde2d6` | 7.59:1 | ✓ |

**禁止する組み合わせ**（実装時のレビュー観点）:

| 組み合わせ | 比 | 代替 |
|---|---|---|
| `#2aa693` / 白 | 3.01:1 | 文字には `accent-strong` を使う |
| `accent-strong` / `accent-soft` | **4.43:1** | `accent-hover` を使う |
| `accent-strong` / `accent-chip` | **4.08:1** | `accent-hover` を使う |

つまり **`accent-strong` を文字に使えるのは 白 / `pref-page` / `accent-tint` の上だけ**。
ヒーロー面（`accent-soft`）とテーマタイルの漢字アイコン（`accent-chip`）の上の文字は
`accent-hover` を使う。参照デザインが `#0E5347` を当てている箇所がこれに相当する。

### 2.4 既存の紫は変更しない

`--primary: #a495d6` / `--primary-accent: #7a6cc0` / `.bg-mirai-gradient` は据え置き。
議案・予算・事務事業評価・チャットなど既存ページの見た目は変わらない。
**トップページの新セクションのみ `pref-*` で組む。**
サイト全体をティールへ移行するかは本設計書のスコープ外（11章の論点）。

なお `Button` / `Badge` の `default` variant は `.bg-mirai-gradient`（薄紫）なので、
トップの新セクションで `Button` を使う場合は `variant="outline"` かクラス上書きで
ティール系に寄せる。ここは実装時に共通ラッパを1つ作るのが望ましい。

### 2.5 角丸・余白・影

| 対象 | 値 |
|---|---|
| ヒーロー・大ブロック | 28〜36px |
| カード | 22px |
| タイル | 18px |
| ピル | 999px（`rounded-full`） |
| セクション間 余白 | PC 40〜48px / スマホ 28〜32px |
| PC 左右マージン | 64px |
| タップ領域 | 最小 44×44px |

**影とグラデーションは使わない。** 面の区別は背景色と `pref-divider` の線で行う。
これは既存の `sm:shadow-lg`（`MainLayout`）や `.bg-mirai-gradient` と方向性が異なるため、
トップページでは `MainLayout` の shadow が付かない経路を通す必要がある（4.2節）。

## 3. フォント設計

### 3.1 Zen Maru Gothic の追加

`web/src/app/layout.tsx` に追加する。

```ts
import { Noto_Sans_JP, Zen_Maru_Gothic } from "next/font/google";

const zenMaruGothic = Zen_Maru_Gothic({
  variable: "--font-zen-maru-gothic",
  subsets: ["latin"],
  weight: ["700"],
});
```

`globals.css` の `@theme inline` に追加:

```css
--font-rounded: var(--font-zen-maru-gothic);
```

- **weight は `700` の1つだけ。** 参照デザインは見出しにほぼ 700 しか使っておらず、
  原案§5の 500 は実使用箇所がないため導入しない。
- `subsets` に `japanese` は**存在しない**（`next/font` の型定義で確認済み。
  `Zen_Maru_Gothic` が受け付けるのは `cyrillic | greek | latin | latin-ext`）。
  これは既存の `Noto_Sans_JP` と同じ状況で、**日本語グリフは preload されず
  unicode-range で遅延取得**される。つまり初期表示のクリティカルパスは太らない。
- `display` はデフォルトの `swap`。日本語見出しは一瞬 Noto Sans JP で描画されてから
  差し替わる（既存の日本語表示と同じ挙動）。

### 3.2 適用範囲（限定列挙）

`font-rounded` を当てるのは以下だけ。**本文・ナビ・ラベル・補足テキストは
Noto Sans JP のまま**にする（触れるグリフ数を抑え、ダウンロード量を減らすため）。

- h1（ヒーロー見出し）
- h2（各セクション見出し）
- h3（下段カードの見出し）
- 委員会カードの問いかけ見出し
- 定例会カードの「◯月」
- テーマタイルの漢字一文字アイコン

### 3.3 Lexend Giga の廃止

以下をすべて削除する。

- `web/src/app/layout.tsx` の `Lexend_Giga` import・定義・`body` の `variable` 付与
- `globals.css` の `--font-lexend: var(--font-lexend-giga);`
- `globals.css` `@layer components` の `.font-lexend { ... }`

根拠:

- 実使用は [web/src/components/top/hero.tsx](../../web/src/components/top/hero.tsx) の2箇所のみ。
  23行目は `siteConfig.features.showTeamMiraiSection` が `false` のため
  **空文字をレンダリングしている**。35行目は `Scroll` の10px表示。
- **この `Hero` コンポーネントは新デザインで丸ごと撤去される**（5.3節）ため、
  廃止後に参照は残らない。
- `subsets: ["latin"]` 指定により**5ウェイトが実際に preload されている**。
  削除はクリティカルパスの純粋な改善になる。

### 3.4 コスト見積もり

現状の実測値（`web/.next/static/media`）:

| 項目 | 値 |
|---|---|
| woff2 ファイル数 | 147 |
| 合計サイズ | 5.3MB（Noto Sans JP 3ウェイト + Lexend Giga 5ウェイト） |
| かな・ラテン等の軽いチャンク | 97ファイル / 平均 19KB |
| 漢字密集域のチャンク | 50ファイル / 平均 72KB |

Zen Maru Gothic 700 の追加でディスク上は **+約1.7MB**。
実ダウンロードは見出しが触れるチャンクのみで **概算 80〜200KB**、しかも遅延取得。
Lexend Giga 5ウェイトの削除で preload 対象が減るぶん、初期表示はむしろ改善が見込める。

## 4. ページ構成

### 4.1 セクション順

**PC（`pc:` = 1000px 以上、参照デザインは 1280px）**

1. ヘッダー（ロゴ / グローバルナビ / 検索）
2. ヒーロー：会期ステータスピル + 見出し + **最新の知事会見カード**（2カラム）
3. 定例会の帯（年4回、4枚横並び）
4. 左2/3：委員会の最新の話し合い（カード4枚 2×2）／右1/3：一般質問から（3件）
5. 気になるテーマから（6タイル横並び）
6. 下段3カード：議員から探す（**今回は非表示**）／県のお金／議案の件数要約
7. フッター注記

**スマホ（`pc:` 未満、参照デザインは 390px）**

1. ヘッダー（ロゴ / 検索）
2. ヒーロー（見出し + 最新の知事会見カードを縦積み）
3. 定例会の帯（2×2）
4. 委員会の最新の話し合い（カード3枚 縦積み）+「委員会をぜんぶ見る」
5. 一般質問から（3件）
6. 気になるテーマから（3列×2行）
7. 小カード2枚：県のお金／議員から探す（**議員は非表示のため実質1枚**）
8. フッター注記
9. **ボトムナビ固定**（ホーム／会見／委員会／定例会／予算）

### 4.2 ブレークポイントとレイアウト幅

**このリポジトリの `md:` は 700px**（Tailwind 既定の 768px ではない）。
PC判定には独自の `pc:`（1000px）を使う。`globals.css` の定義:

```css
--breakpoint-sm: 500px;
--breakpoint-md: 700px;
--breakpoint-pc: 1000px;
--breakpoint-pcl: 1400px;
```

参照デザインの 1280px レイアウトは `pc:` 以上に適用し、
700〜1000px は中間レイアウト（2カラム → 1カラム、委員会カードは1列）として扱う。

**レイアウト幅の制約を外す方法**: 現在 `MainLayout` は通常ページを
`max-w-[700px]` に絞っている（[web/src/components/layouts/main-layout.tsx](../../web/src/components/layouts/main-layout.tsx) 34行目）。
新トップは PC で全幅を使うため、この制約を外す必要がある。

既存の逃がし口 `isWidePage()`
（[web/src/lib/page-layout-utils.ts](../../web/src/lib/page-layout-utils.ts) 27行目）が
`/jimu-jigyo` に対して `max-w-[1440px] mx-auto mt-24` を返しているので、
**ここに `/` を足すだけでよい**。新しい分岐は作らない。

```ts
export function isWidePage(pathname: string): boolean {
  if (pathname === "/") return true;
  return pathname.startsWith("/jimu-jigyo");
}
```

この経路は `sm:shadow-lg` が付かないため、2.5節の「影を使わない」方針とも一致する。

**副作用の確認が必要な点**: `isMainPage("/")` は `true` のままなので、
ヘッダーの `DifficultySelector` はトップに出続ける。新デザインのヘッダーに
難易度セレクタを残すかは実装時に判断し、残さないなら `isMainPage` ではなく
別の判定に切り替える（`isMainPage` は難易度セレクタとチャットサイドバーの
両方に効くため、安易に `/` を外さないこと）。

## 5. セクション別仕様

各節の「データ欠損時」は原案§9の受け入れ基準
「データが無い要素は空欄やプレースホルダを出さず非表示」に従う。

### 5.1 グローバルナビ（PC）

現状 `web/src/components/header/header-client.tsx` は全ブレークポイントで
ハンバーガー（Radix Popover）のみ。横並びナビは存在しない。

- `<nav>` 内に `hidden pc:flex` の横並びピルナビを追加する。
- ハンバーガーは `pc:hidden` にする。
- 現在ページは `bg-pref-accent-strong` + 白文字の塗りピル（5.17:1 ✓）。
  非アクティブは `text-mirai-text`、hover で `bg-pref-accent-tint`。

| ラベル | リンク先 | 備考 |
|---|---|---|
| ホーム | `/` | |
| 質問 | `/questions` | 最新会期へ redirect される既存ルート。PR #44 で対象が「代表質問・一般質問」に広がるため、ピルに収まる短縮形にする（5.7節） |
| 委員会 | `/committees` | |
| 議案 | `/sessions` | 議案一覧の入口。専用ルートが無いため定例会一覧を当てる |
| 知事会見 | `/press-conferences` | |
| 予算 | `/budget` | |

**未使用コンポーネントの扱い**: `web/src/components/layouts/desktop-menu/`（8ファイル）は
どこからも import されていない。現状の `links.tsx` は構成が異なり流用の旨味が薄いため、
**横並びナビは新規作成し、`desktop-menu/` は別PRで削除する**ことを推奨する。

### 5.2 ボトムナビ（スマホ）

- 高さ 72px、5等分グリッド、lucide アイコン + ラベル。**インラインSVG禁止**。
- `pc:hidden` で PC では非表示。
- `env(safe-area-inset-bottom)` を `padding-bottom` に加算する。
- `(main)/layout.tsx` の `<main>` に下余白（`pb-[calc(72px+env(safe-area-inset-bottom))] pc:pb-0`）を
  足し、コンテンツ末尾がナビに隠れないようにする。
- 5枠: ホーム／会見／委員会／定例会／予算。

draft の議案が `is_featured` を立てられてもトップに露出しないようにした。

件数集計を実装する際も**必ず `publish_status = "published"` で絞ること**。
絞り忘れると、未公開のスクレイプ済み議案が件数に乗り、
画面上の件数と「議案をぜんぶ見る」の遷移先の件数が食い違う。

なお新デザインでは「注目の議案」セクション自体をトップから外すため、
#49 が守っている経路（`getFeaturedBills`）は最終的にトップから呼ばれなくなる。
議案一覧ページへ移設する際にこのフィルタを落とさないよう注意する（9章 PR6）。

既存の免責・About・FAQ・利用規約・プライバシーポリシー・GitHub リンクは
現行どおり残す（トップ下部または `Footer`）。

## 6. 新規に必要なデータ項目（AI生成）

**本設計書のスコープ外。別フェーズ・別PRで実施する。**
5章の各セクションはすべて未生成時のフォールバックを定義済みなので、
これが無くてもトップページは成立する。

| 対象 | 項目 | 形式 |
|---|---|---|
| 知事会見の各トピック | `headline_short` | 全角20字前後。問いかけ or 言い切り |
| 委員会の各会議 | `headline_question` | 代表議題を問いかけにしたもの、全角25字以内 |
| 委員会の各会議 | `highlight` | 最も目を引く数値を含む短句（任意・null可）、全角20字以内 |
| 委員会の各会議 | `summary_short` | 1〜2文、全角80字程度。報告内容＋委員の主な要望 |
| 一般質問 | `headline_short` | 既存タイトル流用可。数字があれば含める |

言い換えの例:

- 「一般社団法人九州観光機構の事業について」→「九州観光機構、今年は何をする？」
- 「中東情勢に伴う本県農林水産業への影響について」→「中東情勢、県の農業・漁業への影響は？」

プロンプトには **元の要約に書かれていない情報を足さない**ことを明示する。

実施時は CLAUDE.md の「AI生成コンテンツのDB更新ルール」に従うこと。
特に **生成内容を必ずユーザーに提示して確認を取ってから DB に反映**し、
提示時には日本語の自然さ・情報の整合性・**中国漢字（「议」「务」「该」等）の混入**・
答弁者フォーマットを自己レビューする。

## 7. フォールバック方針（まとめ）

AI生成項目が未整備の状態でもトップが成立することを設計の前提とする。

| 要素 | 本来 | フォールバック |
|---|---|---|
| 会見の話題 | `headline_short` | `press_conference_items.title` をそのまま |
| 委員会の見出し | `headline_question` | `committee_meeting_topics[0].title` |

| 議員カード | 議員テーブル | **カードごと非表示** |

`[開会日]` はプレースホルダ表記であり、そのまま実装してはならない。

## 11. 未決事項・将来の論点

1. ~~**次の定例会の日程データの持ち方**~~ → **#52 で解消**。
   `parseSessionSchedule()` がスクレイピングで開会日・閉会日を取得する（5.5.1節）。
   残る作業は**DBへの投入経路の追加**のみで、これは論点ではなく実装タスク（5.5.2節・9章PR3）。
2. **テーマ体系の統一**。6テーマと既存カテゴリの対応表（5.8節）は当面コード内に持つが、
   本来は議案・一般質問・委員会・会見のすべてにテーマタグを付けたい。
   タグテーブル（`tags` / `bills_tags`）の拡張で賄えるかを含めて検討する。
3. **議員紹介の扱い**。県議会では会派バランスへの配慮が必要。
   議員マスタを新設するか、当面は入口（一覧リンク）のみにするか。
4. **会期中モード（未デザイン）— 優先度を上げる必要がある。**

   原案は「閉会中モードのみ実装し、会期中モードは後回し」を前提にしていたが、
   **#52 のスクレイプ実データを見るとこの前提は成り立たない。**

   令和8年9月定例会の会期は **2026-09-09 〜 2026-10-16**。
   本設計書の作成時点（2026-09-24）で**すでに会期中**であり、
   実装・リリースの想定期間もこの会期に重なる公算が高い。
   参照デザインは閉会中モード（「いまは閉会中」「次の定例会 ◯月◯日から」）しか
   描かれていないため、**このまま実装すると、リリース直後のトップが
   実態と食い違った表示になる**。

   過去の会期を見ても、9月定例会は9月上旬〜10月中旬、2月定例会は2月下旬〜3月下旬と
   **1か月以上続く**（5.5.1節の表）。年間で会期中の期間は決して短くない。

   対応案:

   | 案 | 内容 | 評価 |
   |---|---|---|
   | **A（推奨）** | 会期中モードのデザインをデザイナーに追加依頼し、本設計の範囲に含める | 実態に合う。デザイン待ちが発生する |
   | B | ヒーローのピルとコピーだけ会期中向けに差し替え、レイアウトは閉会中と共通にする | デザイン追加なしで破綻を避けられる。「いま定例会中」ピル + 定例会の帯の `いま開会中` 強調で最低限成立する |
   | C | 原案どおり閉会中モードのみ実装 | **非推奨。** リリース時点で表示が実態と合わない |

   最低でも案Bは必須。5.3節のステータスピルの分岐をそのまま拡張点として使える。
   `getCurrentCouncilSession()` が `null` でない＝会期中の分岐は既に存在する。
5. **サイト全体の紫 → ティール移行の是非**。今回はトップのみ `pref-*` で組むため、
   トップと他ページで系統の異なる2色が併存する。
   移行するなら `--primary` / `--primary-accent` / `--color-mirai-gradient-*` の
   差し替えになり、バナー・ヘッダー選択状態・フッター背景・チャット吹き出しが
   すべて影響を受ける。
6. **議案の件数チップの区分**（5.9.1節）。参照デザインの「条例／工事の契約／購入／計画」は
   `bill_type` の4値とは別軸。どちらで出すかを決める必要がある。
