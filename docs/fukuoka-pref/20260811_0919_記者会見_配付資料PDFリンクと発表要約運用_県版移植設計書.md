# 記者会見 配付資料PDFリンク対応・発表要約運用の県版移植設計書

## 0. 背景と目的

福岡**市**版（`mirai-gikai-fukuoka-city`）で、市長定例記者会見の**発表項目に配付資料PDFリンクを表示**する改修を行い（PR #104 / `9d753a0`）、あわせて会見データ登録の運用方針（発表要約の簡潔化・配付資料URLの紐付け・YouTube URL統一）を確立した。

本書は、これを福岡**県**版（`mirai-gikai-fukuoka-pref`）へ移植するための設計・手順書。

- 移植対象コミット（市版）: `9d753a0`（`feat: 記者会見の発表項目に配付資料PDFリンクを追加`）
- 県版の記者会見機能は市版とほぼ同構造で既に存在する（`web/src/features/press-conferences/`、`supabase/migrations/20260519100000_create_press_conferences.sql`、`packages/seed/fukuoka/seed-press-conferences.ts`）

## 2. 県版と市版の差分（移植時の最重要注意点）

県版は市版のコピーではない。**市版のコードをそのまま貼ると壊れる/不自然になる**箇所があるため、必ず県版に合わせること。

| 観点 | 市版 | 県版 | 影響 |
|---|---|---|---|
| 発言者 `speaker` | `mayor` / `reporter` | **`governor` / `reporter`** | migrationのcheck制約・型・投入データの `speaker` 値がすべて `governor`。市版の `mayor` を機械置換しないこと |
| seed の `ItemInput` 型 | camelCase（`itemType`, `orderIndex`） | **snake_case（`item_type`, `order_index`）** | seed への `material_url` 追加は **snake_case** で行う |
| detail 見出し | 「市からの発表」 | 「県からの発表」 | UI差分の挿入位置は同じだが周辺文言は県版のまま |
| 発表セクション | 常時表示 | **`announcements.length > 0 &&` で条件表示** | PDFリンク追加箇所（発表カード内）は同一。セクション条件はいじらない |
| 話者ラベル | 「高島市長」 | 「服部知事」 | `turn-bubble.tsx`。**事務局区分の追加（3-8）で改修対象**（2分岐→3分岐） |
| 本番 project ref | `xklzpkqtyeuqgawnzgrs` | **`ugvzabneccydyakupfyl`** | Management API / REST の接続先。`.env.production` の `SUPABASE_PROJECT_REF` 参照 |

> 県版 `.env.production` には `SUPABASE_ACCESS_TOKEN` / `SUPABASE_PROJECT_REF` / `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_URL` が揃っており、市版と同じ手順（Management API でのDDL適用・REST でのデータ投入）が使える。

市版には無い県版独自の対応。事務局（担当課）答弁を独立した話者として扱う（背景は 4-3）。material_url とは別件なので **migration も別ファイル**にする。

**(a) check 制約の更新（新規 migration）** `supabase/migrations/20260811091901_add_secretariat_speaker.sql`:

-- press_conference_turns.speaker に事務局区分 'secretariat' を追加

  DROP CONSTRAINT press_conference_turns_speaker_check,
  ADD CONSTRAINT press_conference_turns_speaker_check
    CHECK (speaker IN ('governor', 'reporter', 'secretariat'));

**(b) 型 `Speaker`** `web/.../shared/types/index.ts`:

+export type Speaker = "governor" | "reporter" | "secretariat";

**(c) UI `turn-bubble.tsx`（2分岐→3分岐）**: 現状は `isGovernor` の真偽でラベル・配置・色・アバターを出し分けている。事務局は**県側**として知事と同じ右寄せにしつつ、ラベルとアバターを分ける。

## 4. データ運用ガイド（会見登録時の方針）

配付資料URLカラムを活かすため、会見データ投入時は以下に従う。

### 4-1. 配付資料URLの取得と紐付け

- 県公式の会見ページ（知事定例記者会見の書き起こし/資料ページ）から、配付資料PDFの絶対URLを取得する。
- 各 PDF は対応する**発表項目（announcement）**の `material_url` に紐付ける。質疑（qa）は `material_url = null`。
- 公式ページで「大項目の下に複数の配付資料」がある場合、内容が異なるなら**発表項目を分割**し、それぞれに対応PDFを割り当てる（市版 2026-08-05 の熊本地震支援＝子育て支援／ボランティア講座の分割が前例）。

### 4-2. 発表要約の長尺対策（要点簡潔化）

- 発表（announcement）の `summary` と質疑（qa）の各 `content` は**要点に絞って簡潔化**する。冗長な言い淀み・繰り返しは削る。
- ただし**主張・事実関係・断定/推測の別は変えない**（発言していないことを書かない）。数値・固有名詞・日付は公式書き起こしと必ず照合する。
- 市版の実測目安: 首長ターンは平均 ~190字、長い持論のみ 300字超で許容。県版もこの水準を目安にする。

### 4-3. 事務局答弁の扱い（`secretariat` 区分を新設）

会見では**事務局（担当課・部局）が答弁**することがある。県公式の書き起こしでは、これを担当課・部局名の括弧付き（例「（財政課）」「（防災危機管理局）」「（企画総務課）」）で表記している。市版は知事ターンへ集約したが、県版では `speaker` に `secretariat` を新設し、事務局発言を独立して扱う（実装は 3-8）。

- 事務局の答弁は `speaker = "secretariat"`・`speaker_name = "担当課名"`（括弧を外した課・部局名。例「財政課」）で格納する。
- UIのラベルは `speaker_name` があればそれを、無ければ「事務局」を表示する。
- 知事・記者と取り違えないこと。要点の簡潔化（4-2）は事務局ターンにも同じく適用する。

### 4-4. YouTube URL 形式

- `youtube_url` は既存レコードと形式を統一する（`https://www.youtube.com/watch?v=XXXX`）。`/live/XXXX` や `youtu.be/XXXX` は `watch?v=` 形式へ正規化して格納。投入前に県版の既存レコードを1件確認して合わせる。

### 4-5. データ投入（REST 直接投入スクリプト）

seed への追記ではなく、REST で本番DBへ直接投入する（`press_conferences` → `press_conference_items`（`material_url` 含む）→ `press_conference_turns` の順）。親→子を個別に書くため、子の書き込みが途中失敗すると不完全な会見が残り得る。同一 slug は事前チェックするが、**存在してもitems/turnsが欠損している場合はスキップせず、削除→再投入して整合を回復する**（単純スキップは不完全データを放置するため）。投入後は必ずDBから読み直し、ローカル案と**完全一致**を照合する。

投入スクリプトの要点（市版の構造を流用。県版は話者を `governor`/`reporter`/`secretariat`・県 project ref・`.env.production` に差し替える）:

```python
# press_conference_items の payload に material_url を含める
items_payload = [
    {
        "press_conference_id": conf_id,
        "item_type": i["item_type"],
        "order_index": i["order_index"],
        "title": i["title"],
        "summary": i["summary"],
        "material_url": i.get("material_url"),   # announcement のみ値、qa は null
    }
    for i in data["items"]
]
```

> **CLAUDE.md 必須ルール**: AI生成テキスト（要約・質疑）をDBへ反映する前に、必ず生成内容をユーザーに提示して確認を取る。中国語簡体字/繁体字の混入、話者の取り違え、トピック間の情報混入を自己レビューしてから提示すること。

## 6. リリースと注意点

- **worktree 必須 / 保護ブランチ直接変更禁止**: `git worktree add ../mirai-gikai-<branch> -b fukuoka-pref/feat/... origin/fukuoka-pref/develop`。`.claude/settings.local.json` と `.env`・`.env.production` をコピーし、`pnpm install --frozen-lockfile`。
- **PR は fork（origin）内で完結**: base は `fukuoka-pref/develop`。`gh pr create` はfork環境で base repo を親（team-mirai）に自動解決してしまうため、**`--repo <fork>` を明示**すること（市版で「No commits between」エラーの実績あり）。本家（team-mirai / upstream）への push・PR は禁止。
- **レビューは CodeRabbit**: PR作成後に自動レビューを待つ。Codex（/review-codex）は使わない。
- **`unstable_cache` のシェイプ**: 記者会見の loader は `unstable_cache` 未使用のためキーバンプ不要。将来キャッシュを導入する場合は、`materialUrl` 追加で戻り値シェイプが変わるため `keyParts` をバンプすること。
- **本番DDLの順序**: カラムは本番へ先行適用済みでも、migration ファイルはPRに必ず含める（スキーマ履歴とコードを一致させる）。
