## 1. 前提・福岡県議会の特性

福岡県議会の一般質問は **一括質問一括答弁** 形式。

- 議員がすべての質問を一度に述べる（5〜15分）
- 知事・警察本部長・教育長などが続けて一括で答弁する
- 一部の議員は答弁後に **再登壇するが、全員「要望」のみ**（追加の答弁は発生しない）

### テキストの構造（Shift-JIS）

```
＊永川議員質問
◯四十二番（永川　俊彦）登壇　〔質問全文〕（拍手）

◯副議長（中尾　正幸）　服部知事。
＊知事答弁
◯知事（服部　誠太郎）登壇　〔答弁全文〕

◯副議長（中尾　正幸）　坪田晋議員。（拍手）
＊坪田議員質問
...
```

### 要望発言（第2回登壇）パターン

答弁後に同じ番号の議員が再度登壇し「御要望申し上げます」等で締める。
**知事等の再答弁は発生しない。**
→ 要望テキストは **対応するトピックの末尾に内包する**（後述）。

確認済みの要望発言（令和7年12月定例会）:

| 日 | 議員 | 要望の趣旨 |
|---|---|---|
| 第11日 | 塩出麻里子 | 余裕期間制度の設定件数が少ないことを指摘し、業界の意見を幅広く聴くよう要望 |
| 第11日 | 豊福るみ子 | ストーカー加害者の受診率は「5人に1人」、継続的カウンセリング支援充実を要望 |
| 第12日 | 吉岡玲子 | チャイルドシート貸出制度の周知・体制充実を加速するよう要望 |
| 第12日 | 福地幸子 | 点字ブロックの巡視・修繕の迅速化を要望 |
| 第12日 | 原中誠志 | 能楽堂前庭への屋外ビジョン設置による広報強化を要望 |

```typescript
general_questions: {
  id: string
  council_session_id: string
  questioner_name: string
  questioner_party: string | null
  questioner_number: number | null   // 議席番号（42番など）
  session_day: number                // 第11日 → 11
  question_order: number
  summary: string | null             // AI生成・全体要約
  topics: Json                       // GeneralQuestionTopic[] のJSONB
  raw_text: string | null            // 質問全文
  source_url: string | null
  publish_status: string

```

### 必要な追加カラム

| カラム | 型 | 用途 |
|---|---|---|
| `answer_raw_text` | `text` | 答弁全文（原文モード表示用） |

```sql
alter table general_questions
  add column if not exists answer_raw_text text;
```

### `GeneralQuestionTopic` 型の拡張

既存型に `questioner_follow_up` を追加（任意）:

```typescript
type GeneralQuestionTopic = {
  title: string;                        // テーマタイトル（AI生成・15字以内）
  question_summary: string;             // 質問の要旨（AI生成・60字以内）
  answer_summary: string;               // 答弁の要旨（AI生成・60字以内）
  answerer_role: string;                // 答弁者の役職（例: 「知事」）
  answerer_name: string;                // 答弁者の氏名（例: 「服部誠太郎」）
  block_summary?: string | null;        // 複数トピック統合時のAI生成サマリー（既存）
  questioner_follow_up?: string | null; // 要望発言テキスト（対象トピックに内包）
};
```

スキーマ変更なし（JSONB フィールドの拡張のみ）。

## 5. パーススクリプト設計

`packages/seed/fukuoka/parse-general-questions.py`

### 5-1. テキスト読み込み（Shift-JIS → UTF-8）

```python
with open(path, encoding='shift_jis', errors='replace') as f:
    content = f.read()
```

### 5-2. Q&Aブロック分割

発言区切りの判定ルール:

| パターン | 意味 |
|---|---|
| `＊〇〇議員質問` | 新しい議員の質問開始マーカー |
| `◯NN番（氏名）登壇　` | 発言内容の開始 |
| `◯知事（...）登壇　` | 知事答弁開始 |
| `◯警察本部長（...）登壇　` | 本部長答弁開始 |
| `◯教育長（...）登壇　` | 教育長答弁開始 |
| `◯副議長` / `◯議長` | 司会発言（スキップ） |

**要望発言の判別**: 同じ議席番号が2度目に登壇し、
`答弁いただきました` / `御要望申し上げます` / `要望させていただきます` で始まる場合は要望フラグ。

### 5-3. スクリプト出力JSON構造

```json
{
  "session_day": 11,
  "questioner_number": 42,
  "questioner_name": "永川俊彦",
  "questioner_party": "自民党県議団",
  "question_order": 1,
  "raw_text": "〔質問全文〕",
  "answer_raw_text": "〔答弁全文〕",
  "answerers": [
    { "role": "知事", "name": "服部誠太郎" }
  ],
  "follow_up_text": null
}
```

要望発言がある場合は `follow_up_text` に全文を格納。
AI処理ステップで「最も関連するトピック」の `questioner_follow_up` に振り分ける。

### 5-4. 情報の抽出ロジック

```python
import re

# 議席番号（漢数字）
num_pattern = r'◯([一二三四五六七八九十百千万]+)番'

# 氏名
name_pattern = r'（([^）]+)）'

# 会派（発言冒頭から）
party_pattern = (
  r'(自民党県議団|民主県政クラブ県議団|公明党|新政会|'
  r'無所属の会|ふくおか政策の会|桜和会|豊築会|日本維新の会福岡)'
)
```

## 6. AI処理設計

パーススクリプト出力後、AI呼び出しで `topics` と `summary` を生成。
**AIモデルは1名分でテスト検証してから確定する。**

### プロンプト

```
福岡県議会の一般質問（一括質問一括答弁形式）を以下に示します。

【質問全文 / 永川俊彦 議員（自民党県議団）】
（raw_text）

【答弁全文 / 知事 服部誠太郎】
（answer_raw_text）

---
上記を読んで以下のJSONを生成してください。
トピックは「そこでお尋ねします」「次に、〇〇について」等の境界で分割してください。
question_summary・answer_summary は「〜を問うた」「〜と答えた」などの他者評価調で書いてください。

{
  "summary": "全体の質疑を1〜2文で要約",
  "topics": [
    {
      "title": "トピックタイトル（15字以内）",
      "question_summary": "この質問の要旨（60字以内）",
      "answer_summary": "この答弁の要旨（60字以内）",
      "answerer_role": "答弁者の役職",
      "answerer_name": "答弁者の氏名"
    }
  ]
}
```

要望発言がある場合は追加指示:

```
なお、議員は答弁後に以下の要望を述べています。
最も関連するトピックの questioner_follow_up フィールドに要約（40字以内）を追加してください。

【要望発言】
（follow_up_text）
```

### AI使用量の最適化

| 手法 | 効果 |
|---|---|
| 1回のAPI呼び出しで `topics` + `summary` + `follow_up` を一括生成 | 呼び出し回数を議員数（約21名）に抑える |
| 答弁者が知事のみの場合は `answerer_role/name` を固定値として渡す | 推測させない分トークン節約 |
| 将来: Batch API | コスト50%削減 |

## 7. 表示設計

### 7-1. 要約モード（デフォルト）

各トピックをアコーディオンカードで表示。
展開すると質問要旨・答弁要旨を対で表示。
`questioner_follow_up` がある場合は答弁の下に「議員コメント」として表示。

```
[テーマ1: 欧州からの誘客（これまでの取組）]
  質問  欧州誘客に向け、これまでどのような取組を行ってきたか。
  知事  フランス語での観光情報発信、パリ・ロンドンで観光セミナーを開催。
        延べ宿泊者数はコロナ前比30%増の約10万人泊。

[テーマ2: パリ訪問を踏まえた今後の誘客促進]
  質問  パリセミナーの意見を踏まえ、今後どう展開するか。
  知事  大相撲九州場所の活用、韓国仁川空港経由商品の造成、
        ラ・リストとの食イベント連携を検討。
```

要望発言ありの例:

```
[テーマ: 余裕期間制度の普及]
  質問  公共工事の施工時期平準化に向け、余裕期間制度をどう活用するか。
  知事  令和7年度以降、設定件数を増加させていく方針。
  ──────────────────────
  議員コメント  直近3年の低い設定件数を指摘し、業界の意見を幅広く聴くよう要望。
```

### 7-2. 原文モード

既存の `QuestionViewToggle` で切り替え。
`raw_text`（質問全文）→ `answer_raw_text`（答弁全文）の順で表示。

## 8. シードスクリプト構成

```
packages/seed/fukuoka/
├── parse-general-questions.py       # テキスト→JSON（Shift-JIS変換・構造抽出）
├── generate-topics-with-ai.ts       # AI呼び出しでtopics/summary生成
└── seed-general-questions.ts        # DB投入
```

実行順序:

```bash
# 1. テキスト → 構造JSON
python3 packages/seed/fukuoka/parse-general-questions.py \
  --input "docs/data/令和７年12月定例会（第11日）.txt" \
  --session-id "r7-12" \
  --day 11 \
  --output /tmp/r7-12-day11-parsed.json

# 2. AI呼び出し（topics/summary生成）
pnpm tsx packages/seed/fukuoka/generate-topics-with-ai.ts \
  --input /tmp/r7-12-day11-parsed.json \
  --output /tmp/r7-12-day11-with-topics.json

# 3. DB投入
pnpm tsx packages/seed/fukuoka/seed-general-questions.ts \
  --input /tmp/r7-12-day11-with-topics.json
```
